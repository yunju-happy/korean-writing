# 한국어 문장 규칙

우리가 쓰는 문서는 대부분 **누군가를 설득하거나 움직이려고** 쓴다. 문장이 어색하면 읽는 사람이 내용이 아니라 문장에 걸려 멈춘다. 이 스킬은 그 걸리는 자리를 목록으로 만든 것이다.

**모든 항목은 실제로 지적받은 것이다.** 이론에서 끌어온 규칙은 넣지 않았다. 안 걸리는 규칙은 다음 사람이 지운다.

## 트리거

- "문장 어색한데", "AI 티 나는데", "읽기 좋게", "다듬어줘"
- "이거 좀 더 구체적으로 써주면 좋겠는데"
- PRD·스펙·공지·업데이트 노트·목업 문구·노션 문서를 **남에게 넘기기 직전**

**쓰지 않는 경우.** 영어 문서, 코드·주석, 채팅 대화, 사용자가 쓴 문장을 그대로 인용할 때.

## 에이전트가 API 로 문서를 고칠 때 — 한글을 이스케이프로 바꾸지 않는다

**사람이 IME 로 타이핑할 때는 걸리지 않는 항목이다.** 에이전트가 노션·Confluence 같은 API 로 한글을 넣을 때만 해당한다. 본문 규칙보다 앞에 두는 이유는, 마지막에 읽으면 이미 다 써 버린 뒤이기 때문이다.

**한글을 `\uXXXX` 로 바꿔서 넘기지 않는다. 예외 없다.** 도구는 UTF-8 을 그대로 받는다.

한 자리만 틀려도 **그럴듯한 다른 글자**가 되고, JSON 도 API 도 에러를 내지 않는다. 한글 음절은 코드포인트가 촘촘해서 초성이 같은 글자들이 이웃해 있다.

| 의도 | 실제로 들어간 것 |
|---|---|
| 몫이 | 몷이 |
| 옮기는 | 옆기는 |
| 안팎 | 안팽 |
| 씁니다 | 썽니다 |
| 굉장히 | 굴장히 |
| 가격 | 가것 |
| 센터 | 선테 |

**기계로는 못 잡는다.** 음절 빈도 사전(1,146종)으로 시험하니 열세 개 중 셋만 걸렸고, 2음절 빈도(25,721종)로는 하나만 걸렸다. 「굴장히」 「가것」 「선테」 「옆기는」은 **음절이 다 정상**이라 단어 사전이 없으면 판정이 안 된다. 게다가 과거 출력으로 사전을 만들면 **이미 저지른 오류가 정상으로 학습된다**(「굴장」 15회, 「열심한」 61회). 그래서 검사기를 만들지 않았다 — 「검사기가 잡아 준다」고 믿는 것이 눈으로 보는 것보다 위험하다.

**확인은 두 자리에서 한다.**

- **다시 건드릴 문장은 저절로 걸린다.** 같은 문장을 다음 편집의 `old_str` 로 쓸 때 매칭이 실패하면 깨진 것이다. 실제로 오늘 그렇게 여러 번 발견했다.
- **한 번 쓰고 끝내는 문장만 따로 읽는다.** 그게 위험한 쪽이다. 특히 표 셀.

실제 발생(2026-09-18, 4Q OKR 문서): 한 문서에 **열다섯 번** 깨졌고 사용자가 세 번 지적했다 — *"글씨 깨진게 있는데 수정해"*, *"글자 깨진거 없는지도 스킬에서 봐라"*, *"이스케이프 오류 안나게 하려면 스킬을 어떤 방향으로 고쳐야함?"*

## 0. 넘기기 전에 훑는 30줄

한 번에 다 못 보면 이것만 본다. 아래 절은 각 항목의 근거다.

- [ ] 같은 동사가 세 번 넘게 나오나 — 잡다·짚다·걸리다·갈리다·박다·가르다 (§3-1, §2-1)
- [ ] 부탁·요청의 맺음말이 같은 말로 반복되나 — 「보아 주시기 바랍니다」는 쓰지 않는다 (§1-1)
- [ ] 격을 높이려고 쓴 한자어가 있나 — 소리 내어 말할 일이 없는 말이면 바꾼다 (§1-2)
- [ ] 윗사람·외부인에게 묻는 글(화면 문구 제외)의 질문이 「있어요?·언제예요?」로 끝나나 — 「있나요?·언제인가요?」로 (§1-3)
- [ ] 영어 비유를 그대로 옮긴 명사가 있나 — 천장·바닥·축·지문·덩어리 (§2-1)
- [ ] 「A가 아니라 B」 대구가 두 번 넘나 (§3-2)
- [ ] 긴 문장을 끊었나, 끊은 뒤 앞 문장과 이어 읽히나 (§3-3)
- [ ] 「A가 B하는 C는 N가지입니다」처럼 명사로 묶은 문장이 있나 — 주어로 시작해 동사로 끝낸다 (§3-3)
- [ ] 볼드 소제목과 그 아래 첫 문장이 같은 말인가 (§3-4)
- [ ] 나란히 놓은 둘의 층위가 맞나 (§3-5)
- [ ] 「없는·않는」이 앞뒤 둘 다에 걸리나 (§3-6)
- [ ] 대시(—)가 본문에 두 번 넘게 나오나 (§3-7)
- [ ] 문어체 사이에 「~고요·~거든요」가 섞였나 (§3-8)
- [ ] 붙여 써도 되는 보조 용언을 띄어 썼나 — 「해 주세요」 → 「해주세요」 (§3-9)
- [ ] 부탁하는 글이 길어졌나, 줄글로 이어졌나 — 첫 줄에 부탁, 번호·불릿으로 나누고, 답이 필요하면 끝은 질문 하나 (§3-10)
- [ ] 표 칸에 핵심 값과 그 근거를 같은 무게로 이어 썼나 — 핵심 값을 굵게 앞에 두고, 근거는 줄을 바꿔(`<br>`) 괄호에 (§3-11)
- [ ] 뜻을 특정하지 않는 비유가 있나 (「선다」「닿는다」「조건이 됐다」, §2). 「보여 준다」처럼 뜻이 넓은 동사를 목적어 없이 쓰지 않았나 (§2-1. 「입장 QR은 …부터 보여드려요」처럼 목적어가 있으면 괜찮다)
- [ ] 「여기까지는」「이는」이 무엇을 가리키는지, 「담당」「남은 수업」이 누구의 것인지 분명한가 (§2-3)
- [ ] 「두 겹의」처럼 수만 말하고 각각이 무엇인지 안 밝혔나, 셋 이상을 나란히 늘어놓고 각각을 한 문장 넘게 설명했으면(수를 말하지 않았어도) 번호 목록으로 하나씩 찾게 했나 (§2-4)
- [ ] 처음 꺼내는 사실을 「~인데」나 앞선 참조에 숨겼나 (§2-5)
- [ ] 회원 화면 문구가 기능이 저절로 움직이는 것처럼 「나오다·뜨다·바뀌다」로 적었나 — 「보여드려요·쓸 수 있어요·자동으로 ~돼요」로 다시 쓴다 (§2-6)
- [ ] 문서가 자기 자신을 설명하는 문장이 있나. 소제목 옆 괄호에 메모처럼 끊어 쓴 설명이 있나 (§4-1)
- [ ] 지점장이 읽다가 멈출 용어가 있나 (§4-2)
- [ ] 반대로, 굳은 용어를 풀어 써서 오히려 어려워진 곳이 있나 (§4-2)
- [ ] 확정 안 된 예시가 확정처럼 적혔나 (§4-4)
- [ ] 표에 「무엇을」만 있고 완료 기준이 없나 (§4-6)
- [ ] 그 지표가 다른 정책 때문에 저절로 움직이나 (§4-7)
- [ ] 수식어가 나중에 넓힐 것까지 막고 있나 (§4-8)
- [ ] 위 문서가 아래 문서를 담고 있나 (§4-9)
- [ ] 검토 과정·폐기한 안이 본문에 남았나 (§4-3)
- [ ] **마지막** — 처음 읽는 사람이 되어 끝까지 읽었을 때 멈추는 자리가 없나, 깨진 글자가 없나 (맨 아래 「마지막 점검」)

## 1. 번역투

영어 구문을 한국어 어순에 억지로 얹으면 생긴다. 뜻은 통하는데 읽는 속도가 떨어진다.

| 쓰지 않는다 | 대신 |
|---|---|
| ~를 필요로 하다 | ~가 필요하다 · ~를 원한다 |
| ~에 대하여 / ~에 대한 | ~의 · ~를 (조사로 충분하다) |
| ~를 통하여 / ~를 통해 | ~로 · ~에서 |
| ~에 있어(서) | ~에서 · ~는 |
| ~에 의해 (피동) | 능동으로 되돌린다 |
| ~되어진다 / ~지게 된다 | ~된다 |
| 가지고 있다 | 있다 · 쓴다 |
| ~것이 바로 ~입니다 (도치 강조) | 평서문으로. 「이 데이터를 가장 원하는 곳은 ~입니다」 |
| 그/그녀/그것/그들 (영어 대명사 직역) | 이름을 다시 쓰거나 생략한다 |
| 평평했다 / 횡보했다 (`flat` · `plateaued` 직역) | 거의 그대로였다 · 벗어난 적이 없다 · 1년 내내 2% 대였다 |
| 이 지표가 답을 준다 / 숫자가 보여준다 / 이 표가 말해준다 (`shows`·`tells us` 무생물 주어) | 이 지표를 **보면** ~입니다 · 숫자를 **보면** ~입니다 |
| **A를 B로 읽는다** (`read A as B`) | B라고 **본다** · B로 **이해했다** · B라는 뜻으로 **받아들였다** |

### 1-2. 격식을 차리려다 쓰는 한자어

**남에게 보내는 문서일수록 격을 높이려고 어려운 한자어를 고른다.** 그런데 그 말이 하려던 일을 더 흐린다.

| 쓰지 않는다 | 실제 뜻 | 대신 |
|---|---|---|
| 저희를 **구속하는** 조항 | 이미 정해져 있어 우리가 못 고른다 | **이미 약관에 있어서** 뒤의 판단이 이것을 전제로 합니다 |
| ~에 **기인한다** | ~ 때문이다 | ~ 때문입니다 |
| ~를 **개진한다** | 말한다 · 내놓는다 | 의견을 드립니다 |
| ~함이 **긴요하다** | 꼭 필요하다 | 꼭 필요합니다 |

**판단은 소리 내어 읽어 보면 된다.** 말로 해서 어색하면 글에서도 어색하다 — 「저희를 구속하는 조항이 둘 있습니다」를 입으로 말할 일은 없다.

**「있어 ~ 있습니다」처럼 같은 말이 한 문장에 겹치는 것도 함께 본다.** 위 예에서 「들어 **있어**」와 「둘 **있습니다**」가 겹쳐 더 걸렸다.

실제 발생(2026-09-25, 법률 검토 요청서): *「먼저 이미 약관에 들어 있어 저희를 구속하는 조항이 둘 있습니다」*. 사용자 지적 — *"이것도 말이 좀... 어색하지 않어?"* → *「아래 두 조항은 이번에 고치지 않습니다. 다만 이미 약관에 있어서, 뒤에 나오는 판단이 이것을 전제로 합니다.」*

**반대로 굳은 실무어는 풀지 않는다**(§4-2) — 「공급가액」·「무상 마일리지」·「원가 통제」는 그대로 쓴다. 가르는 기준은 **그 문서를 받는 사람이 그 말을 쓰는가**다.

**「읽다」는 방향에 따라 갈린다.** 피동 「~로 읽힌다」(남에게 그렇게 보인다)는 한국어다. 능동 「A를 B로 읽는다」(내가 그렇게 해석한다)가 직역이다. 실측하면 피동 75회 대 능동 32회로 섞여 있었다.

> ❌ 나온 차이를 그대로 챌린지의 **효과로 읽지는** 않습니다.
>
> ✅ 차이가 나더라도 그게 곧 챌린지의 **효과라고 보지는** 않습니다.

**명사+동사 조합은 대개 멀쩡하다.** 흔히 지적되는 「시간을 가지다」 「논의를 가지다」 「관점을 취하다」는 실측에서 한 건도 없었다. **추상명사에 몸으로 하는 동사를 붙일 때만** 의심한다(읽다·쥐다·취하다·두다).

**다만 명사와 감각이 안 맞는 동사는 의심한다.** 「장면」은 보는 것이고 「이야기」는 듣는 것이다. 「장면을 들려주다」는 뜻은 통해도 읽는 사람이 한 번 멈춘다. 동사에 맞는 명사로 바꾸거나 문장을 다시 쓴다.

> ❌ 정산하다가 트레이너와 감정이 상했던 **장면을** 하나만 **들려주실** 수 있을까요?
>
> ✅ 정산하다가 트레이너와 감정이 상한 적이 있나요? 어떤 일이었나요?

실제 발생(2026-10-26, 지부장 인터뷰 질문지). 사용자 지적: *"장면을 들려준다는 표현이 이상하잖아."*

### 1-1. 부탁·요청의 맺음말 — 「보아 주시기 바랍니다」

**「보아」가 「봐」로 안 줄어서 어색하다.** 문어체로 격을 높이려다 나오는 형태인데, 한국어에서 이 자리는 「봐 주십시오」로 줄거나 아예 다른 동사를 쓴다.

| 쓰지 않는다 | 왜 | 대신 |
|---|---|---|
| **~해 주시기 바랍니다** | **공문서·ARS 안내 투다.** 사람이 사람에게 부탁하는 글에서는 관공서 안내문처럼 들린다 | ~해 주십시오 · ~를 부탁드립니다 · ~주시면 감사하겠습니다 |
| **보아 주시기 바랍니다** | 위에 더해 **「보아」가 「봐」로 안 줄었다** | 검토를 부탁드립니다 · 확인 부탁드립니다 · 짚어 주십시오 |
| **여쭙습니다** | 겸양 문어체라 읽는 사람이 한 번 멈춘다 | **확인하고 싶은 것은 다섯 가지입니다** · 물었습니다 |
| **판단을 받고자 합니다** | 같은 이유 | 알려 주십시오 · 검토를 부탁드립니다 |

**쓸 만한 것은 셋뿐이다** — `~를 부탁드립니다` · `~주시면 감사하겠습니다` · `~해 주십시오`. 이 셋을 돌려 쓰고, 질문을 여는 말은 **「확인하고 싶은 것은 다섯 가지입니다」** 처럼 평서문으로 쓴다. 「확인할 것은 다섯 가지입니다」는 내 할 일 목록처럼 들려서, 남에게 묻는 글에서는 「확인하고 싶은 것은」이 낫다(2026-10-22 원산지 질의 민원 초안. 사용자: *"오히려 이게 더 나은데?"*).

**그리고 맺음말은 문서 전체에서 센다.** 요청서·질의서는 문단마다 부탁으로 끝나서 같은 맺음말이 쌓인다. **세 번을 넘으면 절반은 바꾼다**(§3-1 과 같은 규칙이고, 맺음말은 문단 끝에 있어 반복이 더 눈에 띈다).

실제 발생(2026-09-25, 법률 검토 요청서): 맺음말이 37회였고 그중 **「보아 주시기 바랍니다」가 11회**였다. 사용자 지적 — *"보아 주시기 바랍니다 -> 이거 한글로 이상한데?"* 네 갈래(부탁드립니다 · 여쭙습니다 · 받고자 합니다 · 감사하겠습니다)로 흩어 고쳤다.

**처음에는 「~해 주시기 바랍니다」 자체는 멀쩡하다고 적었다가 되돌렸다**(2026-09-25 같은 날). 「알려 주시기 바랍니다」도 어색하다는 지적을 다시 받았다 — **그 형태 자체가 공문서 투**라서, 「보아」가 안 줄어든 것과는 별개 문제다.

**「~것이 바로 ~입니다」가 특히 잘 빠져나간다.** 강조하려고 도치했는데 읽는 사람은 두 번 읽어야 한다. 실제로 이렇게 고쳤다. *"헬스케어 산업이 필요로 하는 것이 바로 이 데이터입니다"* → *"이 데이터를 가장 원하는 곳은 헬스케어 산업입니다."*

### 1-3. 질문의 맺음말 — 「있어요?」

**윗사람이나 외부인에게 묻는 글에서는 「-어요?」 「-예요?」로 끝나는 의문문 가운데 「-시-」가 없는 것을 쓰지 않는다.** 「있어요?」 「언제예요?」 「어디예요?」는 말로 하면 괜찮아도, 글로 받으면 퉁명스럽게 읽힌다. 인터뷰 질문지·민원·지점장에게 보내는 확인 요청처럼 받는 사람이 미리 읽는 글에서 특히 그렇다. 「~ㄹ까요?」(「결제할까요?」)는 대상이 아니다.

**회원이 보는 화면 문구는 대상이 아니다.** 앱 문구는 친근한 해요체가 기본이고 §2-6 의 말투를 따른다. 「어떤 운동을 좋아해요?」는 그대로 둔다.

| 쓰지 않는다 | 대신 |
|---|---|
| 누가 하고 있어요? | 누가 하고 있나요? |
| 언제예요? · 어디예요? | 언제인가요? · 어디인가요? |
| 무엇이 달랐어요? · 어떻게 됐어요? | 무엇이 달랐나요? · 어떻게 됐나요? |
| 어디서 확인해요? · 어떻게 정해요? | 어디서 확인하나요? · 어떻게 정하나요? |

**「-시-」가 들어간 꼴은 그대로 둔다.** 「하셨어요?」 「바꾸셨어요?」 「받으세요?」는 높임이 이미 들어 있어 공손하게 읽힌다. 한 문서에서 「~나요?」와 섞여도 통일하지 않는다.

실제 발생(2026-10-26, 지부장 인터뷰 질문지): 대상자가 미리 읽는 노션 페이지에 「누가 하고 있어요?」 「언제예요?」 같은 질문을 17줄에 걸쳐 썼다. 사용자 지적: *"있어요? -> 좀 싸가지없자나. 있나요? 이렇게 말투 바꿔줘."*

## 2. 뜻이 비어 있는 표현

가장 잡기 어렵다. **문법도 맞고 읽히기도 하는데 아무것도 특정하지 않는다.** 읽는 사람은 그럴듯하다고 느끼고 넘어가지만 머리에 남는 게 없다.

### 2-1. 비유로 쓰는 동사·명사

「A 위에 선다」는 A와 B의 관계를 말하는 척하면서 무엇 하나 정하지 않는다. 근거로 삼는다는 건지, 다음에 만든다는 건지, 없으면 무너진다는 건지가 문장에서 사라진다.

| 쓰려던 것 | 실제 뜻 | 바꿀 말 |
|---|---|---|
| A 위에 서는 B | A가 없으면 B가 안 된다 | A를 가진 B · A가 있어야 B가 된다 |
| 1호점이 그 기준으로 선다 | 그 기준이 그대로 반영된다 | 1호점에 그 기준이 그대로 들어간다 |
| 지표가 선다 | 측정할 수 있게 된다 | 숫자로 잡힌다 |
| 논리가 선다 | 앞뒤가 맞는다 | 설명이 된다 |
| 전제 위에 선 산출물 | 그 전제가 틀리면 같이 틀린다 | 그 전제에 기대고 있다 |
| 25%에 닿습니다 | 그 숫자가 된다 | 25%가 됩니다 · 25%까지 올라갑니다 |
| 목표에 닿는다 | 달성한다 | 목표를 채운다 · 달성한다 |
| 그 그림에 닿으려면 | 그렇게 되려면 | 그렇게 되려면 |

물리적으로 서는 것(「지점이 선다」)과 닿는 것(「손이 천장에 닿는다」)은 그대로 쓴다.

**목적어를 빼면 뜻이 넓어지는 동사도 같은 문제다.** 「보여 준다」는 무엇을 보여 주는지 목적어가 있어야 하는 일이 정해진다. 목적어 없이 쓰면 하는 일이 사라지고, 엉뚱한 뜻으로 읽히기도 한다. 판정은 동사와 그 목적어를 한 덩어리로 보고 「이 덩어리만 읽어도 하는 일이 하나로 읽히나」를 묻는다. 아니면 하는 일을 그대로 쓴다. 목적어가 있는 쓰임(§2-6 「입장 QR은 11월 4일(수)부터 보여드려요」)은 대상이 아니다. 「숫자가 보여준다」처럼 무생물이 주어인 쓰임은 §1 번역투 표가 따로 다룬다.

> ❌ 돈을 받지 않고 한 번 보여 준다 (무료 체험 수업을 말하려던 것)
>
> ✅ 돈을 받지 않고 한 번 수업을 진행한다
>
> ✅ 회원에게 내 수업 영상을 보여 준다 (목적어가 있어 하는 일이 하나로 읽힌다)

실제 발생(2026-11-18, PT 판매 PRD 다이어그램). 사용자: *"'보여준다'라는 단어가 이상한데? '수업을 진행한다'가 더 맞을거같은데?"*


**실제로 가장 자주 쓰는 여섯 개.** 과거 세션 답변 3,023개(114만 자)를 세어 나온 순서다. 전부 「비유로 쓰는 동사」이고, 바꿀 말이 이미 더 짧고 정확하다.

| 버릇 | 쓴 횟수 | 하려던 말 | 바꿀 말 |
|---|---|---|---|
| **잡다** (목표를 잡다 · 기준을 잡다 · 초안을 잡다) | 357 | 정하다 · 쓰다 | 목표를 **정합니다** · 초안을 **씁니다** |
| **짚다** (한 가지 짚어두면 · 셋만 짚으면) | 113 | 말하다 · 알리다 | 하나 **말씀드릴 게** 있습니다 |
| **걸리다** (규칙에 걸린다 · 걸리는 게 있다) | 66 | 해당하다 · 문제가 있다 | 이 규칙에 **해당합니다** · 문제가 **하나 있습니다** |
| **갈리다** (둘로 갈린다 · 문서가 갈린다) | 54 | 나뉘다 · 어긋나다 | 둘로 **나뉩니다** · 문서와 그림이 **어긋납니다** |
| **박다** (주석에 박아 뒀다 · 기준으로 박아 둔다) | 49 | 적다 · 명시하다 | 주석에 **적어 뒀습니다** |
| **가르다** (가르는 축은 · A와 B를 가르는) | 47 | 나누다 · 구분하다 | **구분하는 기준은** |

**「갈리다」가 특히 나쁘다.** 「둘로 나뉜다」와 「둘이 어긋난다」는 뜻이 거의 반대인데 같은 말을 쓴다. 읽는 사람이 어느 쪽인지 문맥으로 되짚어야 한다.


**명사도 같은 버릇이 있다.** 다만 동사와 달리 **두 갈래로 갈린다.** 한국어에 이미 그 말이 있으면 바꾸고, 자리에 맞게 쓰이는 말이면 횟수만 줄인다.

**(1) 바꾼다 — 한국어에 이미 말이 있는데 영어 비유를 가져온 것**

| 버릇 | 쓴 횟수 | 정체 | 바꿀 말 |
|---|---|---|---|
| **축** (가르는 축은 · 두 축) | 127 | `axis`·`dimension` 직역 | 기준 · 관점 · 갈래 |
| **덩어리** (가장 큰 덩어리) | 37 | 무엇이 큰지 안 말한다 | 가장 큽니다 · 제일 많습니다 |
| **지문** (결정적 지문) | 31 | `fingerprint`·`telltale sign` 직역 | 「이게 보이면 ~다」 · 징후 |
| **같은 결 / 그 결** | 29 | 무엇이 같은지 안 말한다 | 같은 이야기 · 같은 문제 |
| **천장** | 25 | `ceiling` 직역 | **상한** · 최대치 |
| **바닥** | 11 | `floor` 직역 | 하한 · 최소 |
| **관측 창** | | `observation window` 직역 | 관측 기간 |

**「천장」이 대표 사례다.** 같은 글에서 「상한」을 70회 쓰면서 「천장」을 25회 섞었다. 한국어에 이미 있는 말을 두고 영어 비유를 가져온 것이고, 두 말이 섞이면 읽는 사람은 다른 개념인가 되짚는다.

**(2) 자리에 맞으면 그대로 쓴다 — 다만 잦으면 절반은 바꾼다**

| 말 | 쓴 횟수 | 맞는 자리 | 빈 자리 |
|---|---|---|---|
| **신호** | 67 | 징후를 말할 때 — 「재고가 쌓이는 건 수요가 꺾인 신호다」 | 문장 끝을 「~의 신호입니다」로 닫는 버릇. 무엇이 어떻게 된다는 건지 안 말한다 |
| **뼈대** | 24 | 구조를 말할 때 — 「논지의 뼈대」 | 추상명사에 붙일 때 — 「전략의 뼈대」는 전략이 뭔지 안 말한다 |
| **자리** | 104 | 위치·지점 — 「고칠 자리」 | 「그 자리가 문제입니다」처럼 무엇인지 안 밝힐 때. **추상명사를 「자리」로 대신할 때도** 걸린다 — 「두 건의 급한 **자리**가 다릅니다」는 「두 건이 급한 **이유**는 서로 다릅니다」다(2026-09-25 지적) |
| **몫** | 75 | 나눈 부분 — 「센터가 지는 몫」 | 금액이나 비율을 그냥 「몫」으로 뭉갤 때 |
| **나란히 두다 · 나란히 놓고 보다** | 43 | 정말 옆에 둘 때 — 「두 탭을 나란히 두면 대조가 된다」 | 비교를 뜻할 때 — 「재등록률을 나란히 놓고 봅니다」는 **비교합니다**로 쓴다 |

**판단은 바꿔 넣어 보면 된다.** 「징후」나 「부분」으로 바꿔서 뜻이 그대로면 원래 말이 비어 있던 것이고, 어색해지면 제자리에 쓴 것이다.

**「닿다」를 따로 적는 이유.** 숫자·목표에 붙이면 뜻이 「된다」 하나뿐인데, 원래 말보다 그럴듯하게 들려서 손이 간다. 사용자 지적(2026-09-17): *"'닿습니다'도 너무 AI가 쓴 표현같아."*

### 2-2. 구체를 안 말하는 관용구

| 쓰지 않는다 | 왜 | 대신 |
|---|---|---|
| 들어가기 위한 조건이 됐다 | 어디에 들어가는지, 없으면 어떻게 되는지가 없다 | **없을 때와 있을 때 각각 무슨 일이 벌어지는지**를 쓴다 |
| 매물을 기다리는 일이 된다 | 아쉬움만 남고 무엇을 잃는지 모른다 | **누가 정하게 되는지**를 쓴다 |
| ~할 때입니다 / ~해야 할 시점입니다 | 완결 공식형 결말 | 무엇을 언제까지 하는지 |
| X를 넘어 Y로 | 변환 공식 | X와 Y가 어떻게 다른지 |
| 중요한 역할을 한다 / 핵심적인 | 정도만 말하고 내용이 없다 | 무엇을 하는지 |
| 기능을 **낸다** (출시의 뜻으로) | 「내다」는 무엇을 밖으로 꺼낸다는 뜻이라 어디로 나가는지가 없다 | **출시한다** · 배포한다 · 연다 |
| 무엇이 듣는지 / 이게 먹힌다 / 잘 통한다 | 「듣다·먹히다」를 효과의 뜻으로 쓰면 무엇이 어떻게 됐다는 건지 사라진다 | 효과가 있었는지 · 숫자가 움직였는지 · 무엇 때문에 올랐는지 |

실제로 이렇게 고쳤다. *"구독과 무인 운영은 들어가기 위한 조건이 됐습니다"* → *"회원이 헬스장을 고를 때 기본으로 확인하는 항목입니다. 없으면 후보에서 빠지고, 있다고 해서 우리를 고를 이유는 되지 않습니다."*

### 2-3. 가리키는 것이 불분명한 지시어

「여기까지는」 「이는」 「그것은」 「위의」를 쓸 때, **가리키는 대상이 바로 앞 문장에 하나로 특정되는지** 본다. 두 개 이상이면 이름을 다시 쓴다.

실제로 이렇게 고쳤다. *"여기까지는 아직 검증되지 않은 판단입니다"* → *"다만 이 판단은 아직 검증되지 않았습니다."*

**지시어가 없어도 같은 문제가 생긴다. 누구의 것인지를 생략했을 때다.** 쓰는 사람은 머릿속에 대상이 있어서 「담당」 「남은 수업」만 써도 통한다고 느낀다. 처음 읽는 사람은 누구의 담당이 바뀐 건지, 무엇이 남았다는 건지 되짚어야 한다. 소유자를 한 번 넣는다.

> ❌ 마지막으로 **담당 트레이너가** 바뀐 건 언제였나요? **그때 남은 수업은** 어떻게 하셨어요?
>
> ✅ **회원의** 담당 트레이너를 바꾼 일이 마지막으로 있었던 게 언제인가요? **그 회원의** 남은 수업은 새 트레이너에게 어떻게 넘기셨나요?

실제 발생(2026-10-26, 지부장 인터뷰 질문지). 사용자 지적: *"이건 뭔말임?"*

### 2-4. 무엇을 세는지 안 정한 수량 표현

「두 겹의」 「세 갈래로」 「한 축이」 처럼 **단위를 비유로 때우면** 읽는 사람이 무엇이 둘인지 모른 채 다음 문장으로 간다. 수를 말했으면 **그 둘이 각각 무엇인지 그 자리에서 잇는다.**

> ❌ 새 서비스에는 **두 겹의 이유**가 필요합니다.
>
> ✅ 새 서비스에는 이유가 **두 가지** 필요합니다. **하나는 빌려오는 것이고, 다른 하나는 스스로 만들어야 하는 것**입니다.

뒤 문단들이 「빌려오는 것은 ~」 「스스로 만들어야 하는 것은 ~」으로 열리면 대응이 눈에 보인다.

**셋 이상을 말하고 각각을 한 문장 이상으로 설명하면 번호 목록으로 나눈다.** 둘이면 위 예시처럼 「하나는 ~, 다른 하나는 ~」 줄글로 충분하다. **「세 가지」라는 말이 없어도 같다.** 이유·조건·단계를 문단 셋 이상에 나란히 늘어놓았으면, 맨 앞에 「~은 네 가지다」를 한 문장 쓰고 번호를 단다. 문단을 「그런데」 「또」 「시기도」로 이어 붙이면 읽는 사람은 몇 개를 말하는지 끝까지 읽어야 안다. 실제 발생(2026-11-18, PT 판매 PRD 사업적 배경): 이유 넷을 문단 넷으로 쓰고 채팅 요약에만 1~4를 붙였다. 사용자: *"니가 써준거에 1.2.3.4.가 있어서 오히려 맥락을 파악하기 좋았던거같은데 md파일엔 왜 넘버링 생략한거야?"* 채팅 요약에서 번호를 붙여 설명했다면 그 구조가 본문에도 필요하다는 뜻이다. 줄글로 이으면 읽는 사람이 「두 번째가 뭐였지」를 찾으려고 문단을 다시 훑는다. 번호를 붙이고, 항목마다 머리에 짧은 이름을 굵게 단다. 그러면 수를 말한 문장과 각 항목이 바로 짝지어지고, 뒤에서 「2번 경로」처럼 가리키기도 쉽다. 항목 머리 이름을 첫 문장에서 다시 말하지 않는다(§3-4). 그 목록에 들지 않는 것(「이와 별도로」 붙는 것)은 목록이 끝난 뒤 새 문단에 둔다. 각 항목이 문장이 아닌 짧은 말이면 「A, B, C 세 가지」처럼 한 문장에 쓴다. 목록 항목끼리는 서로 떨어진 문장이라 §3-3의 「앞 문장과 이어 읽히나」를 대지 않는다.

> ❌ 회원은 세 가지 경로로 트레이너를 고르고 PT를 산다. 처음 등록한 회원은 웰컴 OT를 받으며 트레이너를 만난다. 특정 트레이너가 궁금한 회원은 그 트레이너의 체험 PT를 사서 받아 본다. 이미 마음을 정한 회원은 프로필과 리뷰를 보고 바로 PT 이용권을 산다.
>
> ✅ 회원은 세 가지 경로로 트레이너를 고르고 PT를 산다.
>
> 1. **웰컴 OT.** 처음 등록한 회원이 받는 수업에서 트레이너를 만난다.
> 2. **체험 PT.** 특정 트레이너가 궁금한 회원이 그 트레이너의 수업을 한 번 사서 받아 본다.
> 3. **바로 구매.** 이미 마음을 정한 회원이 프로필과 리뷰를 보고 PT 이용권을 산다.

실제 발생(2026-11-18, PT 판매 PRD). 사용자: *"세 가지 경로라고 하면 1) 2) 3)으로 각각 어떤건지를 빠르게 찾을 수 있도록 니가 도와주는 식으로 글을 쓰면 어떨까?"*

**분위는 개수가 아니라 비율로 말한다.** 「44곳을 둘로 나누면 하위 22곳이 19.0%」는 읽는 사람이 22÷44 를 먼저 해야 뜻이 잡힌다.

> ❌ 지점을 둘로 나누면 **하위 22곳이 19.0%, 상위 22곳이 32.1%** 입니다.
>
> ✅ **상위 50% 지점은 32.1%, 하위 50%는 19.0%** 입니다.

**개수로 쓰는 자리는 따로 있다.** 둘을 가르는 기준은 「그 숫자가 무엇을 말하려는가」다.

| 말하려는 것 | 쓰는 방식 | 예 |
|---|---|---|
| 분포에서 어디쯤인가 | **비율** | 상위 50% 지점은 32.1% · 하위 25%가 여기에 든다 |
| 이미 해낸 곳이 있다 | **개수** | 32%를 넘는 지점이 **이미 10곳** 있다 |
| 몇 곳을 손대야 하나 | **개수** | 하위 **11곳**을 먼저 방문한다 |

「이미 10곳」을 「이미 23%」로 바꾸면 **「그중 누군가는 하고 있다」는 힘이 빠진다.** 반대로 분포를 개수로 쓰면 읽는 사람이 나눗셈을 한다.

### 2-5. 독자가 아직 모르는 것을 아는 척한다

**처음 꺼내는 사실은 주절에 평서문으로 놓는다.** 종속절이나 되돌아보는 참조에 넣으면 이미 합의된 것으로 읽히고, 독자는 자기가 뭘 놓쳤나 되짚는다.

| 형태 | 왜 걸리나 | 예 |
|---|---|---|
| **「~인데」 전제 강요** | 처음 말하는 숫자를 종속절에 넣어 기정사실로 만든다 | ❌ 80개까지 가는 것이 **목표인데**, 그 속도를 내려면… → ✅ 80개까지 **가려고 합니다.** 그 속도를 내려면… |
| **앞선 참조** | 뒤에 나올 내용을 앞에서 가리킨다 | ❌ 브랜드 정의를 12월로 당긴 **이유가 여기에도 있습니다** (12월 계획은 이 문단 아래에 나온다) → ✅ 그래서 **기존 브랜드를 알리는 일이 새 서비스보다 먼저입니다** |
| **「알다시피」 「앞서 말한」** | 앞에 없으면 거짓말이다 | 정말 앞에 있는지 확인하고 쓴다 |

**쓴 순서대로 한 번 읽으면 잡힌다.** 모르는 말이 나오면 거기가 고칠 자리다.

### 2-6. 화면 문구에서 기능이 저절로 움직이는 것처럼 쓴다

회원이 읽는 화면 문구에서 기능의 움직임을 「나오다·뜨다·바뀌다」 같은 자동사로 적으면, 누가 무엇을 해주는지와 회원이 무엇을 하면 되는지가 함께 빠진다. 「QR이 나와요」는 QR이 저절로 솟는 것처럼 읽히고, 「새 QR로 바뀌어요」는 지금 보는 QR을 곧 못 쓴다는 불안만 남긴다.

**회원 쪽에서 다시 쓴다.** 서비스가 해주는 일이면 주는 쪽을 주어로 삼아 「보여드려요」「알려드려요」로 쓴다. 회원이 할 수 있게 되는 일이면 「쓸 수 있어요」「들어갈 수 있어요」로 쓴다. 시스템이 알아서 하는 일이면 「자동으로 ~돼요」로 써서 신경 쓰지 않아도 된다는 걸 알린다.

| 쓰려던 것 | 고친 것 |
|---|---|
| 11월 4일(수) 0시부터 QR이 나와요 | 입장 QR은 11월 4일(수)부터 보여드려요 |
| 12초 뒤 새 QR로 바뀌어요 | QR은 자동으로 갱신돼요 |

**시스템이 쓰는 정밀한 값은 빼고 스펙에 둔다.** 위 두 줄의 「0시」와 「12초」가 그렇다. 회원이 그 값을 보고 할 일이 없으면 문구에 넣지 않는다. 인증번호 입력 시간처럼 회원이 시간 안에 움직여야 하는 값은 그대로 쓴다.

**결과나 상태를 알리는 문장은 그대로 쓴다.** 「결제가 끝났어요」「예약 시간이 바뀌었어요」처럼 이미 일어난 일을 알리는 문장은 고칠 대상이 아니다. 이 절은 기능이 앞으로 저절로 움직일 것처럼 쓴 문장에만 건다.

실제 발생(2026-10-22, 웹 결제 목업 입장 QR): 「QR이 나와요」에 *«먼가 좀 어색하다»*, 「새 QR로 바뀌어요」에 *«자동 갱신된다는 느낌.. 안정감을 주면 좋겠는디»*.

## 3. 리듬과 구조

### 3-1. 같은 동사·명사 반복

한 문서에서 **같은 말이 세 번 넘으면 글버릇**이다. 절반은 다른 말로 바꾼다. 자주 쌓이는 것은 잡다 · 짚다 · 걸리다 · 갈리다 · 박다 · 가르다 · 서다 · 「~인 셈이다」 · 「~라는 뜻이다」 · 「결국」이다(§2-1 에 실측 횟수).

**추정을 표시하는 말도 한쪽으로 쏠린다.** 같은 집계에서 「~로 보입니다」가 112회인데 「~것 같습니다」는 28회, 「~듯합니다」는 1회였다. 사실과 추정을 가르는 건 맞지만, 그걸 한 가지 말로만 하면 그것도 버릇이다.

### 3-2. 「A가 아니라 B」 대구

한 번은 좋고 두 번부터 기계 같다. 세 번 넘으면 글 전체가 같은 리듬으로 들린다. 논지의 뼈대인 한두 개만 남기고 평서문으로 푼다.

### 3-3. 문장 길이와 이음

**한 문장에 하나만 담는다.** 길이에 정해진 선은 없다. 다만 **짧은 문장이 대부분 더 잘 읽히므로** 길어졌다 싶으면 끊을 자리를 찾는다. 주어가 두 번 넘게 바뀌거나 쉼표가 두 개 넘으면 대개 끊어야 하는 문장이다.

참고로 내 문장은 평균 45자·중앙값 37자인데, 넷에 하나는 60자를 넘고 여덟에 하나는 80자를 넘는다. 그 긴 것들은 예외 없이 여러 개를 쉼표로 이어 붙인 문장이었다.

> ❌ 궁극적으로 FITNERS는 수많은 센터의 필수 솔루션이 **되어** 거기서 쌓이는 데이터를 헬스케어 산업에 **제공하는** 초대형 플랫폼이 **되고자 합니다**.
>
> ✅ FITNERS는 수많은 센터에 없어서는 안 될 솔루션이 되고, 그 안에 데이터가 쌓입니다. 우리는 그 데이터를 가진 플랫폼이 되고자 합니다.

**목적어로 흘려보낸 것을 주어로 세우면** 그게 핵심이라는 게 보인다. 위 예에서 「데이터」가 그렇다.

**「A가 B하는 C는 N가지입니다」처럼 명사로 묶지 말고, 주어로 시작해 동사로 끝낸다.** 명사로 묶으면 무엇을 할 수 있다는 건지가 문장 끝까지 안 나온다.

> ❌ 회원이 사는 방법은 두 가지입니다.
>
> ✅ 회원은 두 가지 방법으로 제품을 구매할 수 있습니다.

같은 문장에서 「사다」를 「구매하다」로 바꾼 것은 받는 사람이 공공기관이라서다(§4-2). 실제 발생(2026-10-22, 원산지 질의 민원 초안): 사용자가 직접 고쳐 주었다.

**끊은 뒤에는 앞 문장과 이어 읽히는지 본다.** 짧게만 만들면 툭툭 끊긴 글이 된다. 새 문장은 **앞 문장이 끝난 자리에서 시작한다.** 앞에서 꺼낸 말을 주어나 화제로 받고, 처음 꺼내는 것은 뒤에 놓는다(§2-5 와 같은 원리다).

> ❌ 지점마다 PT 앱결제 비중이 다릅니다. 하위 절반이 19.0%입니다. 데스크 습관이 원인입니다.
>
> ✅ 지점마다 PT 앱결제 비중이 다릅니다. **하위 절반은 19.0%인데 상위 절반은 32.1%입니다.** 같은 기능을 쓰는데 이만큼 벌어지니, 막고 있는 건 기능이 아니라 데스크 습관입니다.

❌ 쪽은 문장이 셋 다 짧지만 서로 안 물린다. ✅ 쪽은 두 번째 문장이 첫 문장의 「다릅니다」를 숫자로 받고, 세 번째가 그 숫자를 「이만큼」으로 받는다.

**순서도 같이 본다.** 문단 안에서 문장을 어느 자리에 두느냐가 읽는 속도를 정한다. 판단할 것이 두 가지다. **알아야 답을 이해할 수 있는 것이 먼저 나왔나**(배경 → 판단 → 근거), **한 문단이 한 가지만 말하나.** 두 가지를 말하고 있으면 문단을 나눈다.


### 3-4. 소제목과 첫 문장의 중복

볼드 소제목이 이미 말한 것을 첫 문장이 다시 말하면 둘 중 하나를 바꾼다.

> ❌ **센터와 직원의 연결고리를 분리한다.** 프리랜서 계약과 자동 정산으로 **역할을 갈라**, …
>
> ✅ **센터와 직원의 연결고리를 분리한다.** 프리랜서 계약과 자동 정산으로, 센터는 시설로 벌고 트레이너는 자기 수업으로 법니다.

### 3-5. 병렬 층위 불일치

나란히 놓은 둘은 같은 축이어야 대비가 보인다.

> ❌ 센터는 시설 운영으로 **매출을 만들고**, 직원은 수업의 질에 **집중하게** 합니다 (돈 / 태도)
>
> ✅ 센터는 **시설로 벌고**, 트레이너는 **자기 수업으로 법니다** (돈 / 돈)

### 3-6. 부정의 수식 범위

「없는·않는」이 앞뒤 어디까지 걸리는지 본다.

> ❌ 목돈**과** 폐업 걱정 **없는** 선택지 (목돈은 준다는 뜻이 된다)
>
> ✅ 목돈 부담**도** 폐업 걱정**도 없는** 선택지

### 3-7. 대시(—)로 문장을 잇지 않는다

**AI 글의 가장 흔한 지문이다.** 대시는 원래 갑작스러운 전환이나 삽입구에 쓰는 부호인데, 쉼표·괄호·마침표가 들어갈 자리에 아무렇게나 들어간다. 한 문서에 **두 번을 넘으면** 눈에 띈다.

| 쓰려던 자리 | 대신 |
|---|---|
| 이유를 덧붙일 때 | 마침표로 끊고 새 문장 |
| 부연할 때 | 괄호나 쉼표 |
| 열거를 받을 때 | 「전부」 「모두」 「이 셋」 같은 말 |
| **굵은 리드인** 뒤에 설명을 붙일 때 | 리드인을 마침표로 닫고 새 문장으로. 「**판단 기준.** 이 문서를…」 |

> ❌ 작은 평수가 더 잘 잡히는지, 공사가 얼마나 빨리 끝나는지, 손익이 맞는지 **—** 전부 새로 열어봐야 압니다.
>
> ✅ 작은 평수가 더 잘 잡히는지, 공사가 얼마나 빨리 끝나는지, 손익이 맞는지. **이 셋은** 새로 열어봐야 압니다.

**그대로 써도 되는 자리.** 표 안의 좁은 칸, 범위 표기(`10~12월`), 인용 출처. 본문 문장에서만 걸린다.

### 3-8. 문체 혼재

문어체로 가다가 「~것이고요」 「~거든요」 「안 먹히는」 같은 구어가 한 줄 섞이면 그 줄만 튄다. 반대로 구어로 쓴 글에 「~하였다」가 섞여도 같다. **한 문서 안에서는 한쪽으로 맞춘다.**

### 3-9. 보조 용언은 붙여 쓴다 — 맞춤법이 허용하는 만큼

한글 맞춤법 제47항은 보조 용언을 띄어 쓰는 것이 원칙이지만 **붙여 쓰는 것도 허용한다.** 우리 산출물은 **허용되는 자리에서는 붙여 쓴다.** 띄어 쓰면 한 덩어리 동작이 두 낱말로 읽혀 화면 문구가 길고 느슨해 보인다.

| 띄어 쓴 것 | 붙여 쓴다 |
|---|---|
| 확인해 주세요 · 골라 주세요 | 확인해주세요 · 골라주세요 |
| 보여 드려요 · 알려 드려요 | 보여드려요 · 알려드려요 |
| 정해 보세요 · 넘겨 본다 | 정해보세요 · 넘겨본다 |
| 꺼져 간다 · 깨뜨려 버렸다 | 꺼져간다 · 깨뜨려버렸다 |

**붙이면 틀리는 자리는 띄운다**(같은 조항의 「다만」).
- 앞말에 조사가 붙었을 때 — 읽어**도** 보고, 놀아**만** 나는구나
- 앞말이 합성 용언일 때 — 덤벼들어 보아라, 떠내려가 버렸다
- 중간에 조사가 들어갈 때 — 올 듯**도** 하다, 잘난 체**를** 한다
- 보조 용언이 둘 이어질 때는 앞의 것만 붙인다 — 적어둘 만하다
- 「-어 하다」가 구(句)에 붙으면 띄운다 — 먹고 싶어 하다(○) · 마음에 들어 하다(○). 한 단어에 붙어 굳은 말은 원래 한 단어라 붙인다 — 좋아하다 · 싫어하다 · 예뻐하다

**명사 뒤의 「줄」·「보다」는 보조 용언이 아니다.** 「안내 줄」(안내하는 줄)을 「안내줄」로 붙이면 틀린다. 일괄 치환할 때는 앞말이 「-아/-어/-여」로 끝나는 용언인지 보고 붙인다.

실제 발생(2026-10-14, 구독권 구매 목업): 「보여 드려요」를 다른 문구 「알려 드려요」에 맞춰 띄워 썼다가, 사용자가 *«붙여쓰자 최대한»*. 목업 전체를 정규식으로 붙이는 중에 「안내 줄」까지 「안내줄」로 붙어 되돌렸다.

### 3-10. 남에게 부탁하는 글은 무조건 짧게 쓴다

슬랙 DM·스레드·메일로 동료나 외부에 무언가를 부탁하는 글이 대상이다. 받는 사람은 읽고 바로 「할지, 언제 할지」를 정한다. 그 판단에 쓰이지 않는 문장은 전부 읽는 시간만 늘린다.

- **첫 줄에 무엇을 부탁하는지 쓴다.** 배경부터 쓰면 끝까지 읽어야 부탁이 나온다.
- **이유는 한두 문장이다.** 내 쪽 사정(지금 무엇을 만들어 두었는지, 화면에 무엇이 나오는지)은 상대가 할 일을 정하는 데 필요한 만큼만 쓴다.
- **번호와 불릿으로 나눠 한눈에 보이게 한다.** 부탁이 여럿이면 번호를 붙인다. 항목 안에서는 「왜」와 「무엇을 해 달라」를 불릿으로 나눠 한 줄씩 쓴다. 줄글로 이으면 받는 사람이 부탁을 찾아 읽어야 한다.
- **답을 받아야 하면 마지막 줄을 질문 하나로 끝낸다.** 「11/9 배포에 같이 넣을 수 있을까요?」처럼. 답이 필요 없는 부탁(「회의록 올려주세요」)에는 질문을 붙이지 않는다.
- **동료에게는 「~해주세요」로 충분하다.** §1-1 의 세 가지(부탁드립니다 · 주시면 감사하겠습니다 · 해 주십시오)는 외부·윗사람에게 보내는 격식 있는 요청서의 맺음말이다.
- 다 쓴 뒤 문장마다 「이게 없으면 상대가 할 일을 못 정하나」를 묻는다. 아니면 지운다.

> ❌ 웹으로 1일 이용권이 결제되면 웹 결제 알림 채널에 5분마다 알림이 가도록 붙여 두었어요. 지금 한 줄에는 지점, 방문일, 금액, 신규/기존 회원이 나와요. 여기에 어느 광고를 보고 결제했는지까지 같이 보이면 좋겠어요. …(네 문단)
>
> ✅ (번호 항목 하나만 옮김)
> 1. UTM 저장
>    - 왜: 결제 알림에 어느 광고에서 결제했는지도 보이게 하고 싶어요.
>    - 부탁: 결제 토큰 요청 때 UTM 4개를 받아서 이용권 행에 저장해주세요.

실제 발생(2026-10-30, BE 담당자에게 보낼 요청 초안): 네 문단으로 썼다가 사용자가 *«글을 짧게짧게 써»*. 줄였더니 이어서 *«요청하는 문장은 넘버링이나 불릿을 적절히 사용해서 가독성을 높여줘야해»*. 고친 초안을 낼 때 이 스킬을 다시 켜지 않아 §3-9(보조 용언 붙여 쓰기)도 같이 놓쳤다. **초안을 고쳐 다시 낼 때마다 이 체크리스트를 다시 훑는다.**

### 3-11. 표 칸에서는 핵심 값이 먼저 보이게 쓴다

한 칸에 핵심 값(목표치·결론·상태)과 그 근거(비교 수치·출처·이유)를 함께 넣을 때, 둘을 한 문장으로 이어 쓰지 않는다. 같은 무게로 이어지면 읽는 사람이 어느 숫자가 그 칸의 답인지 문장을 끝까지 읽어야 안다. **핵심 값을 굵게 앞에 두고, 줄을 바꿔(`<br>`) 근거를 괄호에 넣는다.**

| ❌ | ✅ |
|---|---|
| 10%. 전체 평균은 6.5%, 상위 25% 지점은 10.1% 이상 | **10%**<br>(전체 평균 6.5%, 상위 25% 지점 10.1% 이상) |

같은 칸에 숫자가 여럿 들어가는 표(목표·현황·기준선)에서 특히 걸린다. 한 칸에 값이 여럿이면 **그 열 제목이 묻는 값**(「목표」 열이면 목표치)이 핵심 값이다. 근거가 한 줄에 들어가지 않으면 괄호에 넣지 말고 표 아래 문장이나 다른 열로 뺀다. `<br>` 이 줄바꿈으로 보이지 않는 곳(슬랙처럼 표가 없는 곳)에서도 근거를 다른 열이나 표 아래 문장으로 뺀다.

이 괄호는 근거 수치와 출처를 모아 둔 것이라 §4-1의 「소제목 옆 괄호에 메모처럼 끊어 쓴 설명」과 다르다. 이유나 해야 할 일을 설명해야 하면 괄호가 아니라 문장으로 쓴다.

실제 발생(2026-11-18, PT 판매 PRD §4-1 목표 표). 사용자: *"이렇게 똑같이 쓰지 말고 10% 한다음 엔터를 쓰고 ( ) 안에 넣던가 해야지. 뭐가 중요한 수치인지가 바로 안보이잖아."*

## 4. 문서에 넣지 말아야 할 것

문장 문제가 아니라 **내용** 문제다. 문체 교정 도구는 이걸 못 잡는다.

### 4-1. 문서가 자기 자신을 설명하는 문장

> ❌ 여기부터는 비전이 아니라 전략입니다. 위의 그림은 안 바뀌지만 아래는 바뀔 수 있습니다.

제목이 「단기 전략 — 2026~2027」이면 그 말은 제목이 이미 하고 있다. **구조 설명은 제목과 순서로 하고 본문에 쓰지 않는다.**

**소제목 옆 괄호에 메모처럼 끊어 쓴 설명도 같은 문제다.** 쓰는 사람이 자기에게 남긴 메모가 그대로 문서에 들어간 꼴이라, 처음 읽는 사람에게는 말을 줄인 지시문처럼 읽힌다. 고치는 방법은 둘이다.
1. **아래 표나 본문에 같은 정보가 있으면 지운다.** 표에 순위 열과 「왜」 칸이 있으면 「위가 우선이다」는 쓸 필요가 없다. 같은 정보가 없을 때만 2번으로 간다.
2. **괄호를 빼고 완결된 문장으로 쓴다.** 소제목을 마침표로 닫고(§3-7) 이유와 그래서 무엇을 하는지를 한 문장에 담는다. 이 문장은 문서의 다른 문장과 같은 맺음(「~한다」)으로 끝내고, 「~할 것」 같은 메모 맺음은 쓰지 않는다.

> ❌ **약속** (이 PRD가 만드는 것이 직접 움직이는 숫자. 위가 우선이다)
>
> ✅ **목표**
>
> ❌ **관찰** (목표 없이 본다. 다른 원인이 섞인다)
>
> ✅ **참고 지표.** 다른 요인에도 영향을 많이 받으므로, 목표로 두지 않고 지켜보기만 한다.

첫째 ✅는 1번(표에 순위와 이유가 있어 제목만 둔다), 둘째 ✅는 2번이다.

**소제목도 작업할 때 쓰던 말로 짓지 않는다.** 「약속·관찰」은 문서를 쓰는 데 참고한 스킬 안의 구분이었다. 읽는 사람은 「목표·참고 지표」처럼 평소에 쓰는 말로 알아본다.

실제 발생(2026-11-18, PT 판매 PRD §4-1 성공 기준). 사용자: *"이거 되게 AI스러운데. korean writing 돌린거 맞아?"*, *"없어도 될 것을 굳이 쓴 느낌"*. 사용자가 직접 「목표」와 「참고 지표 — 다른 요인들에도 영향을 많이 받기 때문에, 목표로 두지는 않되 관찰만 할 것」을 제안했고, 맺음만 「~한다」로 맞춰 반영했다.

### 4-2. 읽는 사람이 모르는 말

우리 문서는 **개발자·PM만 읽지 않는다.** 지점장·트레이너·데스크가 같이 읽는다. 업계 용어나 사내 줄임말이 한 번 나오면 그 사람은 거기서 멈춘다.

| 쓰지 않는다 | 대신 |
|---|---|
| 워크플로우 | 지점이 지금 일하는 방식 · 하던 순서 |
| (전) 접점 | 회원이 보는 모든 곳 · 회원이 마주치는 자리 |
| 거점 | 지점 · 상권 (무엇을 말하는지 골라 쓴다) |
| 온보딩 | 처음 쓰기 시작할 때 |
| 리텐션 | 계속 다니는 것 · 재등록 |
| 퍼널 | 문의에서 등록까지의 단계 |
| 70% 착지 | 「목표의 70%만 달성해도 성공으로 본다」를 줄인 말. **그 관례를 우리가 쓰기로 했는지부터 확인하고**, 쓸 거면 그 문장을 풀어 쓴다 |

**판단 기준.** 이 문서를 지점장이 읽는다고 치고, 멈출 자리가 있나. 있으면 그 말이 문제다.

정말 그 용어가 필요하면 **처음 나올 때 한 번 풀어 쓰고** 그 뒤로 쓴다. 회사 안에서 굳은 말(구독권·이용권·포인트)은 그냥 쓴다.

**반대쪽으로도 틀린다. 굳은 말을 풀면 더 어려워진다.** 위 표를 「한자어를 전부 풀어라」로 읽으면 이 실수가 난다. 한자어인지로 판단하지 않는다. **그 문서를 실제로 받는 사람이 그 말을 쓰는지**를 본다.

| 그 문서를 받는 사람 | 어떻게 |
|---|---|
| 지점장·트레이너·데스크 | 위 표대로 푼다. 워크플로우·온보딩·리텐션·퍼널은 그 사람들이 안 쓰는 말이다 |
| 경영·재무·개발 | 그 직군이 매일 쓰는 실무어는 그대로 둔다. 풀면 길어지고 번역한 것처럼 들린다 |
| 공공기관·법률 담당(민원·질의서·요청서) | 법령이 쓰는 말을 쓴다. 「사다」보다 「구매하다」, 「팔다」보다 「판매하다」. 조문과 같은 말이면 담당자가 해당 조항을 바로 찾는다 |

**위 표의 일곱 개는 여기에 해당하지 않는다.** 그것들은 받는 사람이 누구든 푼다.

아래는 경영 보고서에서 실제로 잘못 푼 것들이다. 오른쪽이 더 쉽다.

| 풀어 쓴 것 | 원래 말 |
|---|---|
| 누가 돈을 대나 | **누가 부담하나** |
| 그냥 공짜로 준 포인트 | **무상 마일리지** |
| 세금 매기는 금액 | **공급가액** |
| 비용 조절 | **원가 통제** |
| 기존 데이터를 옮기는 작업 | **데이터 이관** |

**이 말들은 첫 등장에도 풀지 않는다.** 받는 사람이 이미 쓰는 말이라 바로 위의 「처음 나올 때 한 번 풀어 쓰고」가 걸리지 않는다.

**스펙에 있는 용어는 한 번 더 조심한다.** 원장·적립 줄·사용 줄처럼 스펙이 쓰는 말을 보고서에서만 바꾸면 **스펙과 말이 어긋나고**, 읽는 사람이 다른 것인 줄 안다. 다만 그 문서를 지점장이 받는다면 그때는 첫 등장에 한 번 푼다.

**어휘만 쉽게 해서는 안 풀리는 것이 있다.** 같은 보고서에서 실제로 걸린 셋은 전부 압축해서 뜻이 사라진 표현이었고, 고치는 곳은 §2 다.

| 걸린 것 | 왜 | 고친 것 |
|---|---|---|
| B는 골라 가질 수 없다 | 무엇을 못 고른다는 건지 없다 (§2-2) | 좋은 것만 골라 쓸 수 없다. 정하면 표의 B 칸이 전부 따라온다 |
| 상품권 쪽으로 **밀림** | 「밀린다」가 비유라 무슨 일이 생기는지 없다 (§2-1) | 상품권에 가까워진다. 등록·환급 의무가 생길 수 있다 |
| 거래의 실질로 결정된다 | 추상 명제라 읽고 나도 판단을 못 한다 (§2-2) | 우리가 뭐라 부르든, 돈이 실제로 어떻게 오가는지를 보고 판단한다 |

실제 발생(2026-09-23, 포인트 정산 보고서): 「쉽게 쓰라」는 말을 어휘를 다 푸는 것으로 알아듣고 굳은 말까지 바꿨다. 사용자 지적(2026-09-23): *"누가 부담이 더 쉬운데? 무상 마일리지도 이해할만하고. 공급가액도. 이런 표현은 굳어진 표현이니까 걍 있는 그대로 쓸 때가 더 쉬운 것들도 있잖아."*

### 4-3. 방법론·출처 주석을 본문에

산출 방법, 쿼리 경로, 한계 조건은 **원본 파일 주석이나 각주**에 둔다. 의사결정 문서 본문에 섞으면 읽는 사람이 결론을 못 찾는다.

**검토 과정도 같이 뺀다.** 「처음에는 A로 하려 했는데」 「고민했지만」 「B도 검토했으나」는 **쓴 사람의 여정**이다. 읽는 사람에게는 「아직 안 정했나」로 읽혀 신뢰가 깎인다. 고른 이유만 단정해서 쓰고, 폐기한 안은 결정 기록 문서에 둔다.

> ❌ 처음에는 재등록률로 재려 했는데 두 가지가 걸립니다. …
>
> ✅ 재등록률은 4Q 에 볼 수 없습니다. 재등록은 이용권이 만료돼야 일어나기 때문입니다.


### 4-4. 확정 안 된 예시를 확정처럼

회의에서 오간 후보를 본문에 적으면 정해진 것으로 읽힌다. 남기려면 **「후보」라고 쓰거나 아예 뺀다.**

> ❌ 명상실처럼 작아서 오히려 할 수 있는 것이 후보로 나왔지만 정해진 것은 없습니다.

### 4-5. 상위 문서와 같은 내용 반복

미션과 비전, 전략과 연도별 계획이 같은 이야기를 두 번 하면 **층위가 무너진 것**이다. 각 문서·절이 답하는 질문을 한 문장으로 적어보고, 겹치면 하나로 합치거나 한쪽을 좁힌다.

### 4-6. 「무엇을」만 있고 완료 기준이 없는 표

| 시기 | 무엇을 | **완료 기준** |
|---|---|---|
| 12월 | 가치를 정의한다 | 핵심 메시지 한 문장이 문서로 있다 |

세 번째 열이 없으면 「했다/안 했다」를 매번 다툰다. 일정표를 쓸 때는 **무엇이 있으면 된 것인지**를 같이 적는다.

### 4-7. 그 지표가 다른 변화와 섞이지 않는지

완료 기준으로 숫자를 걸 때, **다른 정책 때문에 저절로 움직이는 숫자인지** 먼저 본다. 섞이면 그 숫자가 올라도 아무것도 증명하지 못한다.

> ❌ 신규 회원 중 **할인 없이 정가로 등록한 비율**이 오른다
> → 구독권으로 전환하면 깎을 구조 자체가 없어져 브랜드와 무관하게 오른다.
>
> ✅ 신규 회원 한 명을 데려오는 데 드는 **광고·전단지 비용**이 내려간다
> → 상품 구조가 바뀌어도 이 숫자는 브랜드만 따라 움직인다.

**자문할 것.** 이 숫자가 올랐을 때 «우리가 잘해서»말고 달리 설명할 길이 있나. 있으면 그 지표는 못 쓴다.

### 4-8. 범위를 가두는 수식어

지금 하는 일로 대상을 좁혀 쓰면, **나중에 넓힐 때 문장부터 고쳐야 한다.** 상위 문서(미션·비전·정책)일수록 크게 잡는다.

> ❌ **운동하는 모든 사람**의 건강을 다루는 플랫폼 (마사지·시술·식단은 밀려난다)
>
> ✅ 사람들이 **몸을 돌보는 모든 일**을 다루는 플랫폼

좁힌 것이 의도라면 **왜 좁혔는지 한 줄**을 붙인다. 안 붙이면 다음 사람이 그 울타리를 사실로 읽는다.

### 4-9. 상위 개념이 하위 개념보다 좁지 않은지

미션 ⊃ 비전 ⊃ 전략 ⊃ 분기 목표. **위가 아래를 담지 못하면 아래가 위를 벗어난 것**이고, 읽는 사람은 어느 쪽이 진짜인지 모른다.

> ❌ 미션 「**피트니스 센터**의 문제를 해결한다」 · 비전 「**헬스케어 산업**의 데이터 플랫폼이 된다」
> → 비전이 미션 밖으로 나가 있다.

문서를 다 쓴 뒤 **위에서 아래로 한 번 읽으며 「이게 저 안에 들어가나」**를 확인한다. 안 들어가면 위를 넓히거나 아래를 좁힌다. 대개 위를 넓히는 게 맞다. 아래가 회사가 실제로 가려는 곳이기 때문이다.

## 고칠 때의 순서

1. **§4부터 본다.** 넣지 말아야 할 것이 있으면 문장을 다듬어도 소용없다.
2. **§3 구조를 잡는다.** 긴 문장을 끊고, 층위를 맞추고, 반복을 센다.
3. **§1·§2 표현을 바꾼다.** 여기가 제일 눈에 띄지만 가장 나중이다.
4. **소리 내어 한 번 읽는다.** 숨이 차는 자리가 끊어야 할 자리다.
5. **처음 읽는 사람이 되어 처음부터 끝까지 읽는다.** 아래가 이 스킬의 마지막 관문이다.

### 마지막 점검 — 처음 읽는 사람이 헷갈리지 않고 읽히는가

앞의 규칙을 다 지켜도 **글 전체가 안 읽히는 경우**가 있다. 항목별로 고치다 보면 문서를 이미 아는 사람의 눈으로 보게 되기 때문이다. 넘기기 전에 **그 문서를 처음 보는 사람이 되어 위에서 아래로 한 번** 읽는다.

멈추는 자리가 있으면 거기가 고칠 곳이다. 대개 다음 넷 중 하나다.

| 멈추는 이유 | 어디를 고치나 |
|---|---|
| 처음 나온 말인데 설명이 없다 | §2-5 · §4-2 |
| 이 숫자가 어디서 나왔는지 모르겠다 | 근거를 그 자리에 한 줄 |
| 앞에서 한 말과 다르게 읽힌다 | 둘 중 하나를 고쳐 맞춘다 |
| 왜 이 이야기가 지금 나오나 | 순서를 바꾸거나 이어주는 한 줄을 넣는다 |

**소리 내어 읽는 것과는 다른 점검이다.** 소리 내어 읽기는 문장 하나하나의 호흡을 보고, 이건 **문서 전체가 한 번에 이해되는지**를 본다.

**깨진 글자가 없는지도 본다.** 특히 **표 셀과 두세 글자짜리 구절**을 본다. 긴 문장은 틀리면 앞뒤가 안 맞아 저절로 눈에 띄지만, 「안 옴」 「몫이」 「안팎」처럼 짧은 것은 문맥이 없어서 틀린 채로 읽힌다. 자세한 것은 맨 앞 「에이전트가 API 로 문서를 고칠 때」 절에 있다.


**의미를 바꾸지 않는다.** 표현을 덜어내다 주장까지 덜어내면 롤백한다. 수치·고유명사·직접 인용은 손대지 않는다.
